# @chatprd/icons

ChatPRD's own icons, used across chatprd.ai and the ChatPRD app. There are two families:

- **Line icons (100):** 24px, stroke-based, `currentColor`. There are 33 product concepts (document, template, prototype, project, scorecard, agent, MCP, integrations, and so on), 56 UI glyphs (chevrons, close, check, search, and so on), and 11 app-state and tool icons (tool, tool call, running, queued, streaming, pending, stop, cancelled, retry, disconnected, right panel). There are also two animated components, `IconSpinner` and `IconStreamingDots`.
- **Spot icons (12):** full-color, tonal product illustrations of the core concepts (one hue family each, plus neutrals), for feature cards, empty states and onboarding. Each has a full drawing (64px grid) and a simplified small drawing (24px grid), in 14 tones (7 for the site, 7 that follow the app's theme).

Released as **`@chatprd/icons`** tarballs on [GitHub Releases](https://github.com/ChatPRD/chatprd-icons/releases), with semver. See the [CHANGELOG](./CHANGELOG.md). Code is MIT; the icon artwork is © ChatPRD, all rights reserved (see [LICENSE](./LICENSE)).

- **Preview:** `npm run preview` builds the package and serves a static page at http://localhost:4600 with every line icon at 16, 20, 24 and 32px, the animated icons, and every spot in every tone on white and on Ink. CI also uploads it as the `icon-preview` artifact on every PR.

## Install

Install a release tarball directly; no registry account or token is needed:

```bash
npm install https://github.com/ChatPRD/chatprd-icons/releases/download/v1.0.1/chatprd-icons-1.0.1.tgz
```

That adds `"@chatprd/icons": "https://github.com/ChatPRD/chatprd-icons/releases/download/v1.0.1/chatprd-icons-1.0.1.tgz"` to your `package.json`. To upgrade, change the version in that URL (both places) and reinstall.

`react` 18 or later is a peer dependency.

## Imports

```tsx
// Root import. The package is marked sideEffects: false and every icon is its own module,
// so bundlers keep only what you import.
import { IconDocument, IconChevronDown, SpotDocument } from "@chatprd/icons";

// Deep imports, one module per icon (named and default exports).
import IconSearch from "@chatprd/icons/icons/search";
import { SpotAgent } from "@chatprd/icons/spots/agent";
import { IconSpinner, IconStreamingDots } from "@chatprd/icons/animated";
```

Raw SVGs ship in the package for Figma, slides, email, OG images and anything that isn't React:

| Import path | What it is |
|---|---|
| `@chatprd/icons/svg/<name>.svg` | Line icon (`currentColor` stroke) |
| `@chatprd/icons/color/<name>.svg` | Full spot, brand tone (64×64) |
| `@chatprd/icons/color/<tone>/<name>.svg` | Full spot in another tone (`tint`, `rose`, `coral`, `violet`, `ink`, `white`, `app`, `app-*`) |
| `@chatprd/icons/color-small/<name>.svg`, `color-small/<tone>/<name>.svg` | Small spot (24×24) |
| `@chatprd/icons/manifest.json` | Names, concepts, tags, what each icon replaces, the palette and spot metadata |

In Node or a build script: `require.resolve("@chatprd/icons/svg/document.svg")` gives the file path. On disk they're in `node_modules/@chatprd/icons/svg/` and so on.

`react` (>=18) is a peer dependency. The output is ESM with `.d.ts` types.

## Line icons or spot icons?

| Use a **line icon** when… | Use a **spot icon** when… |
|---|---|
| It sits inline with text or controls: buttons, nav, menus, inputs, table rows, chips, toasts, status. | It's the visual anchor of a block: a feature card, an empty state, an onboarding step, an upgrade prompt, a "what's new" card. |
| It's 12–32px. | It's 20–32px (small drawing) or 40–64px (full drawing). See the sizing table below. |
| It should take the text color (black or neutral, per the design guidelines). | It should add a small, deliberate moment of color. |
| There are many on screen. | There are a few on screen: one per card, with no more than about 4–6 in a row. |

Rules for spot icons:

- **One idea per spot, and only the matching concept.** `SpotDocument` means docs and PRDs. Don't use it as a generic decoration.
- **Don't mix families in one row.** A card grid uses all spot icons or all line icons.
- **Neutrals are real materials; brand color marks the meaningful part.** White, paper, gray, charcoal and ink are real colors, not just backgrounds. Where an object is realistically neutral (a page, window, book or speech bubble), draw it in neutrals and put brand color (pink, coral or purple) only on the one meaningful part. A few spots are brand-led (agent, team, integrations, project). Green, amber, red and blue appear only as small semantic accents. **Security is the gold shield (semantic trust): do not change it.**
- **Place them on white or Ink (`#0B0A10`).** Don't put them on brand art, the vivid Agents band, or a tinted card, where the colors fight. They're drawn to work on both white and dark.
- **Keep them out of the hero and out of dense app chrome.** The hero shows the product, and app UI uses line icons.
- **Label them in context.** Spots are `aria-hidden` by default, like line icons, so the card title carries the meaning. Pass `title` only if the spot stands alone.

## Usage

```tsx
import { IconDocument, IconChevronDown } from "@chatprd/icons";

<IconDocument size={20} className="text-black/60" />
<IconChevronDown size={16} strokeWidth={2} />
<IconScorecard title="Scorecard" />   // labelled: role="img" with a <title>
```

Props match lucide's common props, so most swaps are a rename:

| Prop | Default | Notes |
|---|---|---|
| `size` | `24` | Sets `width` and `height`. Tailwind `h-4 w-4` classes still win, as they do with lucide and heroicons. |
| `strokeWidth` | `1.75` | Lucide's default is 2. Don't pass `strokeWidth={2}` out of habit. |
| `absoluteStrokeWidth` | `false` | Same as lucide: keeps the rendered stroke at `strokeWidth` px at any size. |
| `className` | | Merged with `chatprd-icon chatprd-icon-<name>`. |
| `aria-hidden` | `true` | Icons are decorative by default. |
| `title` | | When set, the icon gets `role="img"`, a `<title>` and `aria-labelledby`, and is no longer hidden. |
| any SVG prop | | Spread onto the `<svg>`, e.g. `fill="currentColor"` for a filled rating star. `ref` is forwarded. |

`chatprdIcons` maps every kebab-case name to its component, for string-keyed menus such as the app's `ui/Icon.tsx`. `ChatPRDIconName` is the union of those names.

### Loading and streaming

```tsx
import { IconSpinner, IconStreamingDots, IconLoader, IconStreaming } from "@chatprd/icons";

<IconSpinner size={16} />            // animated: anything in flight (saving, generating, uploading)
<IconStreamingDots size={16} />      // animated: a response is being written
<IconLoader size={16} />             // static "loading" glyph, e.g. in a legend or a status filter
<IconStreaming size={16} />          // static "streaming" glyph
```

The animation is CSS inside the SVG, so it needs no global stylesheet and no `animate-spin` class. Under `prefers-reduced-motion: reduce`, the spinner stops and shows the static `loader` arc, and the dots stop pulsing and show at full opacity. Pair either one with visible or screen-reader text ("Generating…"), since the icon is `aria-hidden` by default.

### Spot icons

```tsx
import { SpotDocument, chatprdSpots, chatprdSpotTones } from "@chatprd/icons";

<SpotDocument size={56} />                    // full drawing, brand tone
<SpotDocument size={24} />                    // small drawing (auto at size ≤ 32)
<SpotDocument size={40} variant="small" />    // force the small drawing
<SpotDocument size={28} variant="full" />     // force the full drawing
<SpotDocument size={56} tone="rose" />        // mono rose
<SpotDocument size={56} tone="white" />       // on ink or brand art
<SpotScorecard title="Scorecards" />          // labelled, if it stands alone
```

There are 12 spots, one per core concept: `document`, `template`, `project`, `scorecard`, `coaching`, `prototype`, `agent`, `integrations` (also used for MCP), `team`, `knowledge`, `chat` and `security` (also used for enterprise). Spot props are `size`, `tone`, `variant`, `title`, `className` and any SVG prop. Colors come from the tone, not `currentColor`.

#### Sizing

| Size | Use | Notes |
|---|---|---|
| 12–32px | **Line icons**, for UI chrome: nav, buttons, menus, inputs, table rows | `currentColor`, black or neutral |
| 20–32px | **Small spots**, for colored moments beside 14–16px text: nav items that need identity, list rows, chips, tabs, menu headers | A simplified drawing on a 24px grid with at most two tones plus white and no hairlines or text bars. Chosen automatically when `size` is a number ≤ 32. |
| 40–64px | **Full spots**, for feature cards, empty states, onboarding steps and upgrade prompts | Default 56. Use `variant="full"` if you really need the full drawing below 32px. |

#### Tones

| `tone` | What it does | Use it when… |
|---|---|---|
| `brand` (default) | White/paper surfaces with brand-color identity (pink, coral, purple) and rare semantic accents | Mixed sets on white or ink, e.g. a features grid. This is the default for marketing. |
| `tint` | The spot's **line icon** geometry, stroked in its lead color (pink, purple or gold) with closed shapes filled at 18%, like the app's DuotoneIcon. Exports are in `color/tint/` and `color-small/tint/` (24px viewBox). | App UI and dark mode, where a lighter touch than the full spot fits. It aligns exactly with the line icons. |
| `rose`, `coral`, `violet` | Every spot renders in that one brand family plus neutrals (security's gold shield too). The second color becomes the family's lighter tone, the third (integrations) its deep tone, and a semantic accent its light tone. | A section already has a color, e.g. a pink onboarding flow or a purple "prototypes" page. Use `rose` when in doubt. |
| `ink` | Grayscale (ink, charcoal, mid and light gray) | Quiet contexts on light backgrounds: docs, settings, disabled or locked states, print. |
| `white` | White planes at several opacities, with dark cut-outs for details | Dark surfaces, the vivid Agents band, brand art and photos. Don't use it on white. |

| `app` | Each spot uses its **app** tone (below), through the app's CSS variables, so it follows the app's light and dark themes | Inside the ChatPRD app. |
| `app-accent`, `app-violet`, `app-pink`, `app-rose`, `app-teal`, `app-slate` | Every spot in one app tone | App surfaces that already have a category color. |

#### App tones

`tone="app"` renders every color through CSS variables, so icons follow a host app's light and dark themes, with light-mode hexes as fallbacks:

- **Family colors:** `--ds-accent`, `--tone-violet`, `--tone-pink`, `--tone-rose`, `--tone-teal` and `--tone-slate`. `base` uses the variable, `light` and `highlight` use it at 55% and 18% opacity, and `deep` uses `color-mix(in srgb, var(--tone-x) 72%, #000)`.
- **Neutrals:** `--panel`, `--surface`, `--surface-active`, `--text-4` and `--text`.
- **Green and orange (`--ds-green`, `--ds-orange`) are reserved for states** (success and warning), so they aren't spot families.
- **Security** uses `--icon-gold`, falling back to `#E39200`.
- **Raw SVGs** in `color/app*/` and `color-small/app*/` use the light-mode hexes, because design tools can't read CSS variables.

Judge app icons at 16, 20 and 24px (the small tier), and use the full drawing only at 40px and up.

**Line icons in the app** already inherit `currentColor`, so color them with the app tokens rather than hexes: `<IconDocument className="text-[var(--tone-pink)]" />`, or `style={{ color: "var(--ds-accent)" }}`. Neutral nav and controls should stay on `--text-2` or `--text-3`, and only category moments should get a tone. Use `--ds-green` and `--ds-orange` only for states, paired with a recognizable glyph (`check-circle`, `alert-triangle`).

Rules of thumb: use one tone per row (don't mix `brand` and mono spots side by side); use mono when the surrounding section has a color and brand when it doesn't; and on art or dark backgrounds use `white` rather than a brand tone.

## Design spec

**Grid.** 24×24 viewBox with 2px padding, so artwork sits in the 20×20 live area (2–22). Strokes may reach the padding edge but not past it. Square shapes are about 17×17, circles have a radius of 8.5, and tall or wide shapes are about 15×18.

**Stroke.** 1.75px at 24px, `currentColor`, round caps and joins. There are no fills, except accent dots.

**Geometry.** The set takes its geometry from the ChatPRD mark, which is built from interlocking pills (stadiums) drawn in one even line inside a soft squircle (corner radius about 26% of the size).

- Corners are soft: a radius of 3.5–4.5 on containers (documents, windows, cards, calendar), where lucide uses 2. Small parts use a radius of 1–2.25.
- Use pills and ovals where lucide uses rectangles. Chat is an oval bubble rather than a square one, and `integrations` is two offset, interlocking pills that echo the mark.
- Containers that hold another symbol (external link, compose, share, prototype) are drawn open, with a gap where the symbol crosses the edge, rather than overlapping it.
- Lines inside a document or list get shorter toward the end (for example 7, then 4.5) so they read as text, not as a hamburger menu.
- No diagonal folded corners. The document fold is a rounded notch.

**Accent dots.** Filled `currentColor` circles with a radius of 1.1–1.5, used only where they carry meaning: the period on info, alert and help; the agent's eyes and antenna; the spark on `sparkle`; the start of `roadmap`; the date on `calendar`; the lock's keyhole; and the ellipsis on the `more-*` icons.

**Color.** Icons inherit text color. On chatprd.ai, line icons are black or neutral (`text-black/60` and similar), never accent-colored.

**Sizes.** The icons are drawn to work at 16, 20, 24 and 32px. At 16px, prefer the default stroke, since dropping to 1.5 makes the soft corners look faint. Above 32px, use `absoluteStrokeWidth` or a lighter `strokeWidth` (1.5).

### Spot icon spec

**Keyline grid.** Every spot sits centered on one keyline, so the set reads at the same visual size and weight (`manifest.spotGrid.keylines` and `smallKeylines`; each spot lists its `keyline`).

| Keyline | Full (64 grid) | Small (24 grid) | Spots |
|---|---|---|---|
| circle | Ø52 | Ø20 | team |
| square | 46×46 | 18×18 | template, agent, integrations |
| portrait | 42×52 | 16×20 | document, scorecard, security |
| landscape | 54×42 | 20×16 | project, prototype, coaching, chat, knowledge |

**Standards** (`manifest.spotGrid.standards`): cards and pages use radius 4, small parts radius 1.5, text bars are 3px with round ends, detail strokes are 3px (such as template's brackets), and symbol strokes are 4px (checks, arrows). Every white surface gets the same 1px `#E7E4EA` hairline. Brand color mass should be similar from icon to icon.

The full brief, including the reasoning and acceptance checks, is in [docs/spot-icon-brief.md](./docs/spot-icon-brief.md). In short:

- **Grid.** 64×64 viewBox with 4px padding, rendered at 48–64px (default 56).
- **Same picture as the line icon.** Each spot traces its line icon at ×64/24 (proportions, curves and positions), with the strokes turned into flat planes. At 48px they should obviously be the same picture.
- **Style.** Flat, crisp and editorial, to match the site's UI (12px card radii, hairline borders, flat stat colors). Mostly tonal, product illustration rather than clip art. There are no shadows, no thickness edges or bevels, and no puffy forms.
- **Color.** Neutrals first: white, paper, light and mid gray, charcoal `#3A3640` and ink are materials. Then one **lead** brand family (pink, coral or purple), optionally a **second** brand family that neighbors it on the brand gradient (pink + coral, pink + purple), drawn as flat planes. `integrations` alone uses all three, separated by value (peach, hot pink, deep purple). On top of that there may be at most one small **semantic accent**: green for success, amber for warning, red for error, blue for info. **Gold is the semantic trust color and leads only the security shield, which the build check locks.**
- **Edges.** White pages and cards get a 1px light-gray (`#E7E4EA`) hairline so they read on white. Otherwise there are no outlines; edges come from tone changes.
- **Gradients.** Effectively none: flat planes, with at most one subtle single-hue tone shift where it adds form (the shield's lighter left half, the coaching bubble's lighter top band). Codegen still accepts single-hue `linearGradient`s, but use them rarely.
- **Geometry.** Corner radii are about 2–3px on cards and pages and 1–2px on small parts, with straight edges where the line icon has them. Proportions are precise, not inflated. Nothing is thinner than 1.5px at 64, except the hairline.
- **Agent.** The agent is the line icon's friendly robot head: a very rounded head, two round eyes and an antenna dot. There are no brows, mouth or visor, so it never reads as angry.
- **Palette** (`manifest.palette`, deep → base → light → highlight):

  | rose (hot pink) | `#C1125A` | `#FF2E7E` | `#FF4FA3` | `#FFE6F0` | Brand identity |

- **Codegen checks** (`manifest.spotRules`, run by `npm run icons`, `npm run check` and CI):
  - Every fill, stroke and gradient stop must be in `manifest.palette`.
  - Each spot uses its manifest `lead` family. `lead`, `second` and `third` must be brand families (`spotRules.brandFamilies`: rose, coral, violet), and `second`/`third` must form an allowed pair or triad with the lead. The one exception is `spotRules.semanticLeads` (security → gold), and `spotRules.requiredLeads` makes the build fail if security ever stops leading with gold. Green, amber, red and blue may appear only as the one `accent`. Neutrals, including charcoal and ink, are always allowed as materials.
  - Amber never leads, so the old orange + yellow combination can't occur.
  - Each gradient stays within one family (or neutrals). Multi-hue gradients are rejected, as are filters, masks, rasters and transforms.
  - Across the set, pink (rose) must appear in at least 8 spots, and no family may lead more than 6.
  - Gradient ids are scoped per instance at render time, so many copies of a spot can share a page.
  - **Tones** (`manifest.spotTones`): codegen maps every color to a role (`lead.deep|base|light|highlight`, `accent.*` or `neutral.*`) and re-renders each spot per tone. The `brand` render must reproduce the source SVG exactly, and the build fails otherwise. Each mono tone may only use its family plus neutrals, `ink` only the ink grays plus neutrals, and `white` only white plus the knockout ink. Shapes marked `data-ko="1"` in the source are details drawn on top of a colored shape. They render normally in every tone except `white`, where they become a dark cut-out so they stay visible.
  - **Small tier** (`manifest.spotSmall`): every spot needs a `color-small/<name>.svg` on a 24×24 grid, using the same lead family and at most two colors plus white, with no gray hairlines or lines. It gets the same tone exports.
- **Background.** Every spot must read on both white and Ink `#0B0A10`. Check both in the preview.

## Naming

- File and manifest names are kebab-case **concepts, not shapes**: `document`, not `file-text`; `integrations`, not `plug`; `scorecard`, not `clipboard-chart`. The name should say what the icon means in ChatPRD.
- Components are `Icon` plus the name in PascalCase: `document-check` becomes `IconDocumentCheck`.
- Use suffixes for variants: `-add`, `-check`, `-off`, `-circle`. Directions use `-up`, `-down`, `-left` and `-right`.
- Generic UI glyphs keep their conventional names (`chevron-down`, `close`, `more-horizontal`) so they're easy to find.
- `manifest.json` `replaces` lists the exact library export names. A name with a parenthetical, such as `"Plug (MCP settings pages)"`, means it replaces that icon only in that context. Codegen and the audit treat it as a hint, not as a one-to-one mapping.

## Adding or changing an icon

1. Draw it on a 24×24 artboard with a 2px keyline, using a 1.75px centered stroke with round caps and joins. Start from a neighbouring icon so corner radii match.
2. Export or hand-write a flat SVG: one `<svg>` with `viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.75" stroke-linecap="round" stroke-linejoin="round"`, containing only `path`, `circle`, `rect`, `line`, `polyline`, `polygon` and `ellipse`. Don't include groups, transforms, ids, `<title>`, or editor metadata. If you export from Figma, run it through SVGO and then check that the root attributes match.
3. Save it as `svg/<name>.svg`.
4. Add an entry to `manifest.json` with the `name`, `group` (`product`, `ui` or `status`), `concept`, `tags` and `replaces`.
5. Run `npm run icons`. It validates every SVG against the spec and regenerates the tone exports and the TypeScript modules.
6. Run `npm run preview` and check the icon at all four sizes.
7. Run `npm run check`, `npm run build` and `npm test`, then open a PR. CI runs the same steps and uploads the preview page as an artifact.
8. Release it (see [Releasing](#releasing)).

**Spot icons** follow the same steps, with these differences (and every spot needs both a full and a small drawing):

- Draw the full spot on a 64×64 artboard and save it to `color/<name>.svg`. Draw the small spot on a 24×24 artboard (start from the line icon, filled) and save it to `color-small/<name>.svg`. Mark details that sit on top of a colored shape with `data-ko="1"`. The root is `<svg viewBox="0 0 64 64" fill="none">`. Each shape sets its own `fill` (a palette hex or `url(#gradient)`), or `stroke` and `stroke-width`, plus an optional `opacity`.
- Add an entry to `manifest.spots` with the `name`, `concept`, the matching line icon in `line`, the `lead` family and, if used, the `accent` family.
- Only use colors that are in `manifest.palette`, and gradients only within one family, defined in a single `<defs>` block of `linearGradient`s with `gradientUnits="userSpaceOnUse"`. To add a family, add all four tones and check it on white and on Ink.

**Animated icons** live in `src/animated.tsx`, which is written by hand. Keep the keyframes inside the SVG, and always add a `prefers-reduced-motion: reduce` rule that stops the motion.

## Releasing

Versions follow semver. For the icon set that means:

- **Patch:** geometry or color fixes that keep every name and prop (a nudged path, a corrected hex).
- **Minor:** new icons, spots or tones; new optional props.
- **Major:** a renamed or removed icon, spot or tone, a changed default (size, stroke, tone), or a changed import path.

To release:

1. Update `CHANGELOG.md` and bump `version` in `package.json` (and `manifest.json` `version` if the manifest's shape changed), in a PR.
2. After it merges, tag `main`: `git tag v1.2.0 && git push origin v1.2.0`.
3. The **Release** workflow checks that the tag matches `package.json`, runs the checks, build and tests, runs `npm pack`, and attaches `chatprd-icons-<version>.tgz` to a GitHub Release.
4. Consumers pick it up by changing the release URL in their `package.json`.

Don't replace a published tarball. If a release is broken, release the next patch.
